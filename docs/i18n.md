# 国际化（i18n）

> 定位：平台机制类 · 人类阅读
> 单一事实来源：`src/shared-services/i18n/*`（类型/服务/种子）、`src/db/schema/translation.ts`（两张翻译表）、`src/components/providers/*`（Provider 与 hooks）
> 引用关系：← 被 architecture-overview、README「文档」索引、i18n skill 链接；→ 引用 i18n 代码单一事实来源
> 更新触发：i18n 分层 / 语言检测链路 / 缓存策略 / 新增语言或新增内容翻译机制变更时

## 概述

本项目采用**中文原文作为翻译 key** 的国际化方案，基于 i18next + react-i18next，前台 SSR 页面与管理端翻译管理共用一套基础设施。翻译按用途分为两层：

- **UI 翻译**（`ui_translation` 表）：前台页面固定文案，key 为中文原文（如 `t("首页")`），目标语言映射到英文值；进程内按 locale 惰性全量缓存。
- **内容翻译**（`content_translation` 表）：实体字段（如新闻标题/摘要/正文）的按需翻译，默认语言（zh）存主表原字段，其它语言翻译按 `(entityType, entityId, fieldName, locale)` 定位；无缓存、按需查询。

> 事实以代码为准：支持语言、Seed 清单、缓存实例、表清单分别见 `i18n.types.ts`、`i18n.seed.ts`、`i18n.ui.cache.ts`、`src/db/schema/translation.ts`。

## 两层翻译模型

| 维度 | UI 翻译 | 内容翻译 |
|------|---------|---------|
| 表 | `ui_translation` | `content_translation` |
| 用途 | 前台固定文案 | 实体字段（新闻标题/摘要/正文…） |
| 定位键 | `(locale, key)`，key 为中文原文 | `(entityType, entityId, fieldName, locale)` |
| 缓存 | `uiTranslationCache` 按 locale 惰性全量 | 无缓存，按需查询 |
| 合并 | i18next 直接读取 resource | `applyTranslations()` 覆盖主表字段 |
| 默认语言 | zh 直接返回 key（资源恒空） | zh 存主表原字段，不做翻译合并 |

> 表结构、唯一约束与索引以 `src/db/schema/translation.ts` 为准（`entityId` 为 uuid，要求所有可翻译实体使用 uuid 主键）。

## 语言检测与 SSR 加载

每次请求按下列链路确定语言并渲染，`localeMiddleware` 是 locale 默认值的唯一权威来源（非法 Cookie 值回退 `zh`）：

```mermaid
sequenceDiagram
    participant Req as HTTP 请求
    participant MW as localeMiddleware
    participant CTX as context.locale
    participant ROOT as __root.tsx loader
    participant FN as i18n.functions.ts
    participant UI as i18n.ui.server.ts
    participant Cache as i18n.ui.cache.ts
    participant DB as ui_translation
    participant PROV as GlobalStore / I18nProvider
    participant C as 组件

    Req->>MW: 进入请求（requestMiddleware 链）
    MW->>CTX: 解析 lang Cookie → locale（非法回退 zh）
    ROOT->>FN: getLocaleBundleSFn()
    FN->>UI: getUITranslations(locale)
    alt zh（源语言）
        UI->>UI: 直接返回 {}（免查库）
    else en（目标语言）
        UI->>Cache: get(locale)
        alt 缓存命中
            Cache-->>UI: 返回翻译
        else 缓存 miss
            UI->>DB: loadUITranslations(locale)
            DB-->>UI: 全量翻译
            UI->>Cache: set(locale, 翻译)
        end
    end
    FN-->>ROOT: { locale, translations }
    ROOT-->>PROV: locale + translations
    PROV->>C: useTranslation() / useLocale()
```

> 管理端（`/admin/*`）为中文 SPA，根 loader 对 `/admin` 前缀**跳过** UI 翻译加载（不注入 `GlobalStoreProvider`）；详情见 `src/routes/__root.tsx`。

## 目录与文件结构

`shared-services/i18n` 分层清晰：**共享基础件**（类型/实例/种子/SFn/barrel）+ **两个平行子域**（UI 翻译 / 内容翻译），各自携带 schema、server 逻辑，其中 UI 翻译另有缓存。命名统一为 `i18n.<子域>.<role>.ts` 点号约定（与 `config.*` / `dict.*` 一致）。

```
src/shared-services/i18n/
├── i18n.types.ts            # 共享类型 + locale 常量（客户端安全，可任意模块引用）
├── i18n.config.ts           # createI18nInstance —— i18next 实例（客户端安全）
├── i18n.seed.ts             # ensurePresetTranslations —— 英文种子数据
├── i18n.functions.ts        # Server Function 包装器（getLocaleBundleSFn 等）
├── i18n.server.ts           # 服务层 barrel：统一 re-export 下两子域服务与类型
├── i18n.ui.server.ts        # UI 翻译 服务层（查询/维护/导入导出）
├── i18n.ui.schemas.ts       # UI 翻译 zod schema（formSchema / getListSchema / deleteSchema）
├── i18n.ui.cache.ts         # uiTranslationCache（MemoryCache，按 locale 分片）
├── i18n.content.server.ts   # 内容翻译 服务层（含 translateRecord/Records）
├── i18n.content.schemas.ts  # 内容翻译 zod schema
├── i18n.content-io.ts       # 内容翻译 导入导出
└── __tests__/               # i18n.test.ts / i18n.seed.test.ts / i18n.config.test.ts
```

> **`.server.ts` 命名约束**：`i18n*.server.ts` 带 `.server` 分界标记，受 TanStack Start `importProtection` 保护（客户端禁止导入），服务层逻辑必须保留该后缀。
> **barrel 说明**：`i18n.server.ts` 是下两层服务的统一导出入口（非具体服务实现），路由/领域经它引用即可，避免逐条深链。

## 缓存与写路径

- **UI 翻译缓存**：`i18n.ui.cache.ts` 的 `uiTranslationCache` 按 locale 存储整份 `Record<key, value>`，首次访问惰性加载（miss → 查库 → 写缓存）；**zh 恒返回空资源**（源语言，免查库）。管理端保存/删除/导入后调用 `refreshUITranslationCache(locale)` **仅失效缓存 key**，由下一次读取懒加载重建。
- **内容翻译无缓存**：按 `(entityType, entityId, locale)` 精确查询，随业务量增长仍可控，不做缓存。
- **系统配置翻译缓存**：`content_translation` 中 `entityType === "system_config"` 的记录由 config 模块以 `configTranslationCache` 独立缓存（`getConfigTranslations` 懒加载）；内容翻译 upsert/delete/import 在判定 `system_config` 时直接调用 `refreshConfigTranslationCache(locale)`（i18n 侧直接依赖 config，见 `i18n.content.server.ts`）。
- **写入约定**（`i18n.ui.server.ts` / `i18n.content.server.ts`）：ID 分支按 id 直改；新建分支基于唯一约束做**原子 `onConflictDoUpdate`**，消除并发 select-then-write 竞态。
- **导入**（`importUiTranslations` / `importContentTranslations`）：按唯一键去重后**批量 `onConflictDoUpdate`** 一次写入（单次预查询统计新增/更新），避免逐条 select；内容导入在事务内完成，并规范化 `valueType`（拷贝数据，不污染入参）。

```mermaid
flowchart TD
    A[管理端 保存/删除 翻译] --> SFN[Server Function handler]
    SFN -->|UI 翻译| UIW[i18n.ui.server.ts<br/>upsert / delete]
    SFN -->|内容翻译| CTW[i18n.content.server.ts<br/>upsert / delete]
    UIW --> DUI[(ui_translation)]
    UIW --> REFUI[refreshUITranslationCache<br/>仅失效 key → 懒加载重建]
    CTW --> DCT[(content_translation)]
    CTW -->|system_config| REFC[refreshConfigTranslationCache]
    SFN --> IMP[导入: 批量 onConflictDoUpdate]
    IMP --> DUI
    IMP --> DCT
    IMP -->|system_config| REFC
```

## 实体翻译接入

在实体服务（`services/<module>/<module>.server.ts`）中组合查询与合并，路由 loader / SFn 层按 `context.locale` 调用：

```ts
const records = await listRecords(...);                 // 主表（zh）数据
const locale = context.locale;                          // 由 localeMiddleware 注入
const translated = await translateRecords(records, "实体类型", locale); // i18n 通用入口
```

- 默认语言直接返回主表记录（`translateRecords` 对 zh 短路）。
- **批量**走 `translateRecords(entityType, ids[], locale)` 一次查询按 entityId 分组，避免 N+1；单条用 `translateRecord`。
- 业务侧**无需声明可翻译字段**——`content_translation` 中实际存在的记录即被合并（`存在即生效`）。
- 服务端 `translateRecord` / `translateRecords` 由 `shared-services/i18n` 统一提供，业务只调用不实现。
- 管理端通过 `FieldTranslationDrawer`（`components/admin/forms/FieldTranslationDrawer.tsx`）编辑字段翻译，字段定义（含 `name`/`label`/`valueType`）由调用方直接透传，`valueType` 仅供 UI 选编辑器，不进入服务端契约。

> **依赖方向**：i18n → config 存在单向依赖（内容翻译写 `system_config` 时刷新 config 缓存），引用方避免反向依赖 config → i18n 的业务逻辑。

## 管理端维护

| 能力 | 说明 |
|------|------|
| UI 翻译管理 | `/admin/translations/ui`（`translation:view`/`translation:manage`）——按语言/关键词检索、增删改 |
| 内容翻译管理 | `/admin/translations/content` ——按实体类型/语言/关键词检索、增删改 |
| 导入 / 导出 | 两项均支持 JSON 导出与导入（`translation:export` / `translation:import`） |
| AI 翻译（单字段） | `FieldTranslationDrawer` 内单个字段的「AI 翻译」按钮 → 调用 `aiTranslateFieldSFn`（非流式，提示词 `ai_translation_prompt`，为空则报错） |
| AI 批量翻译（单实体） | `FieldTranslationDrawer` 的「AI 批量翻译」→ 统一 `aiBatchTranslateSFn`（客户端传 `records`（id+源字段值）+ `fields` + `mode`，SFn 流式返回 `Response`），按 `batchSize` 把多实体打包为一个 JSON 一次调用（提示词 `ai_translation_batch_prompt`），支持 fill（补齐缺失）/ correct（AI 校正已有），`writeBack=false` 仅回填编辑器。**未做全表批量翻译** |

> 权限码定义见 `src/permissions/admin-permissions.ts`；管理端为中文 SPA，管理页文案不参与翻译。
> 默认语言（zh）为源语言，在翻译管理端只读：不出现在新增/筛选的语言下拉中，表中的 zh 条目仅可查看不可编辑/删除。

## AI 批量翻译（抽屉单实体）

`FieldTranslationDrawer` 的「AI 批量翻译」以 **Server Function 流式返回**实现（handler 返回 `Response`，TanStack Start 置 `x-tss-raw: true`，客户端经 SFn 调用直接拿到流式响应读取 `data: {json}`）：

- **入口与鉴权**：统一 `aiBatchTranslateSFn`（`shared-services/i18n/i18n.functions`，`adminPermGuard(TRANSLATION_MANAGE)`）——客户端把要翻译的 `records`（`[{ id, values }]`，单实体为一条）、字段声明 `fields`、`mode` 传入；`writeBack=false` 时仅回填编辑器，用户确认后手动保存。
- **组批**：`buildBatchTasks` 按 `mode` 计算每个实体每个目标语言需要翻译的字段（fill 仅 `content_translation` 无记录字段，correct 仅已有记录字段再生成并覆盖），并按 `batchSize`（默认 10）把多个实体打包为一个 JSON 调用一次 AI（减少调用次数）。
- **流式**：`runBatchTasks` 逐批经 `streamAiChat`（`@tanstack/ai` 流式）生成，转发 `text-delta`（AI 实时原文），批末 `extractJsonFromText` 从累积文本提取 JSON（纯文本提取，不依赖厂商 `response_format`，OpenAI 兼容通用）；SSE 依次下发 `batch-start` / `text-delta` / `batch-done`（进度）/ `failed` / `done`（汇总）事件，批末回填编辑器（`writeBack=true` 时可 `upsertContentTranslations` 落库），整批失败收集后继续后续批次。
- **约定**：未做全表批量翻译——取数由前端提供（客户端拥有要翻译的记录），不耦合 `services`；`valueType` 仅为 UI 编辑器类型字符串，不进入服务端契约；`ai_translation_batch_prompt` 与 `ai_translation_prompt` 均为系统配置，为空时直接报错（不内置兜底）。
